# Typed handlers: a union of questions, each with its own answer

This document will show what the `handler` union option generates and how to use it, with the example of a user directory.
You will learn:

- how to declare a union where **each variant says what it answers with**
- what `mkunion` **generates** from that: a handler interface, a typed `Ask`, and two handlers for tests
- how a query is **data**, so it can arrive as JSON and be dispatched in five lines
- when to reach for this, and when a plain `Match` is enough

The [effect system](./effect_system.md) example builds on this page. You do not need it to use what is here.

## Working example

A user directory can answer three questions:

- `GetUser` - one user by ID, or nothing
- `FindUsers` - every user whose name starts with a prefix
- `CountUsers` - how many users there are

The three answers have three different types: `*User`, `[]User`, `int`. That is the whole problem. A union gives one interface for the three questions, but `MatchQueryR1` gives one `T` for all three arms. Somewhere, the answer type has to be tied to the question.

**Notice** the embedded `f.Returns[...]`. It has no fields and no methods, and nothing happens at runtime. It is a label: `GetUser` answers with `*User`, `CountUsers` with `int`. Serde, TypeScript export and JSON schema skip it.

**Notice** the `handler` option in the tag. It tells `mkunion` to read the labels and generate the typed layer below. Without the option, the union is a plain union, with `Match` functions and JSON as usual.

## What is generated

Six things, from `example/query/query_union_gen.go`. The first is the one you implement:

```go title="example/query/query_union_gen.go (generated)"
// One typed method per variant. Add a variant and every handler stops compiling.
type QueryHandler interface {
	HandleGetUser(ctx context.Context, op *GetUser) (*User, error)
	HandleFindUsers(ctx context.Context, op *FindUsers) ([]User, error)
	HandleCountUsers(ctx context.Context, op *CountUsers) (int, error)
}

// A Query that answers with R. *CountUsers is a QueryOf[int] and nothing else.
type QueryOf[R any] interface {
	Query
	HandleQuery(ctx context.Context, h QueryHandler) (R, error)
}

// The untyped form, for code that dispatches any query: an endpoint, a bus.
func QueryHandlerFunc(h QueryHandler) func(ctx context.Context, op Query) (any, error)

// Answers everything with a zero value. Embed it in a test handler.
type QueryDefaults struct{}

// A handler made of functions. A nil function answers with a zero value.
type QueryFuncs struct {
	GetUser    func(ctx context.Context, op *GetUser) (*User, error)
	FindUsers  func(ctx context.Context, op *FindUsers) ([]User, error)
	CountUsers func(ctx context.Context, op *CountUsers) (int, error)
}
```

(The sixth, `Perform` and `Answer` on each variant, lets a query be put to a handler value that serves several unions. The effect system uses it; this page does not.)

Why an interface with one method per variant, and not one generic method? Go interfaces cannot carry generic methods. So the per-variant answer type lives in two places the compiler can read: on `QueryOf[R]`'s type parameter, and in `QueryHandler`'s method signatures. `QueryOf[R]` is what makes `Ask` below infer its result.

## When to use it

| You have | Use |
|---|---|
| Variants that all answer with the same type, such as commands that answer with the next `State` | a plain union and `MatchXR1` (see [state machines](./state_machine.md)) |
| Variants that each answer with their own type: queries, requests, RPC | `handler`: one interface, typed answers, `Defaults` and `Funcs` for tests |
| Operations a program asks for and something else performs | `handler` plus the [effect system](./effect_system.md) |

The option needs a union without type parameters. Every variant must embed `f.Returns[R]`; `mkunion` says which one does not.
